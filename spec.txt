1. Executive Summary
tpt-teleop-space is the hyper-optimized, zero-bloat, fault-tolerant, Rust-based middleware workspace designed for the most isolated, unforgiving, and high-stakes robotics environment in existence: outer space.
While other domains face harsh physical or adversarial conditions, space robotics face absolute isolation. A Mars rover experiences 4 to 24 minutes of light-speed communication delay. A deep-space probe operates for decades with zero possibility of physical repair. Satellites endure extreme thermal cycling, hard vacuum, and relentless ionizing radiation that flips bits in memory (Single Event Upsets, or SEUs).
tpt-teleop-space orchestrates planetary rovers, satellite constellations, orbital servicing vehicles, and deep-space probes. It is built on a foundation of Delay-Tolerant Networking (DTN), radiation-hardened software architectures, predictive onboard autonomy, and deterministic, zero-allocation control loops. Every design choice prioritizes mission survival, data integrity, and absolute reliability over decades of operation.

Space-Grade Software Note: Spaceflight software requires rigorous adherence to standards like ECSS-E-ST-40C (Software Engineering) and NASA-STD-8739.8. tpt-teleop-space is architected to support these certifications: no dynamic memory allocation after initialization, no recursion, no panics in the hot path, and complete traceability of all state transitions.

tpt-t-space-dtn: Delay-Tolerant Networking. A custom, zero-allocation implementation of the Bundle Protocol (BPv7) and Licklider Transmission Protocol (LTP) for store-and-forward communication across multi-hour blackouts.
tpt-t-space-predictive: Onboard model-predictive control (MPC) and autonomous decision-making. Enables complex maneuvers (e.g., autonomous landing, hazard avoidance) without ground-in-the-loop intervention.
Vehicle-Specific Execution
tpt-t-space-rover: Planetary surface operations. Wheel odometry, visual-inertial odometry (VIO), autonomous hazard avoidance, and robotic arm sample collection sequencing.
tpt-t-space-satellite: Attitude Determination and Control System (ADCS). Reaction wheel control, star tracker fusion, momentum dumping, and orbit maintenance maneuvers.
tpt-t-space-orbital: Rendezvous and Proximity Operations (RPO). 6DOF relative navigation, autonomous docking/berthing, and space robotic arm (e.g., Canadarm-style) manipulation.
Environment & Survival
tpt-t-space-radiation: Software fault tolerance. Implements memory scrubbing, Triple Modular Redundancy (TMR) voting on critical calculations, and Single Event Upset (SEU) detection and recovery.
tpt-t-space-thermal: Thermal management. Monitors heater states, radiator deployment, and battery temperatures. Triggers "Safe Mode" power shedding if thermal limits are breached.
tpt-t-space-power: Power subsystem management. Solar array pointing optimization, battery charge/discharge cycle tracking, and load shedding during eclipse periods.
Edge & Hardware Interface
tpt-t-space-edge: Bare-metal RTOS execution layer. Direct register-level control for space-grade microcontrollers (e.g., RAD750, LEON3, or modern rad-hard ARM Cortex-R). Includes hardware watchdog management and watchdog-feeding logic.
tpt-t-space-ccsds: Consultative Committee for Space Data Systems protocol parser. Zero-allocation parsing of CCSDS telemetry and telecommand packets (TM/TC).
4. Extreme Performance Tactics (Space-Specific)
Space environments demand performance tactics that assume the hardware is degrading, the network is disconnected, and a single flipped bit could end a billion-dollar mission.
4.1. Radiation-Hardened Software (Rad-Hard SW)
Hardware rad-hardening (e.g., silicon-on-insulator) is expensive and lagging behind commercial performance. Software must compensate.
The Solution: tpt-t-space-radiation implements continuous memory scrubbing. A low-priority background task continuously reads static memory, calculates a CRC32, and corrects single-bit errors using Hamming codes before they accumulate into multi-bit failures.
TMR Voting: Critical calculations (e.g., ADCS quaternion updates) are executed three times on separate cores. A custom voter compares the results. If one core suffers an SEU and diverges, the voter masks the bad result and triggers a core reset, all in <50 microseconds, with zero heap allocation.
4.2. Delay-Tolerant Networking (DTN)
TCP/IP fails catastrophically with 20-minute round-trip times and frequent link blackouts (e.g., planetary occultation).
The Solution: tpt-t-space-dtn implements a custom, zero-copy Bundle Protocol. Commands and telemetry are encapsulated in "bundles" with custody transfer. If a link drops, the bundle is stored in non-volatile memory (NVRAM). When the link restores, transmission resumes exactly where it left off.
Zero-Allocation: Bundles are serialized directly into pre-allocated NVRAM sectors using rkyv. No dynamic memory is used during network blackouts.
4.3. Deterministic, Zero-Allocation ADCS Control
A satellite tumbling out of control is a mission-killer. Attitude control loops must run at high frequencies (100Hz+) with absolute determinism.
The Solution: tpt-t-space-satellite runs the ADCS control loop on a pinned, real-time core. It fuses star tracker, sun sensor, and gyro data using a custom, SIMD-accelerated Multiplicative Extended Kalman Filter (MEKF) for quaternion estimation. The loop executes in <200 microseconds.
No Panics: All mathematical operations (e.g., matrix inversion) use bounded, fallback algorithms (e.g., pseudo-inverse with condition number checking) to guarantee the loop never panics or divides by zero, even with corrupted sensor data.
4.4. Predictive Autonomous Hazard Avoidance
A Mars rover cannot wait 12 minutes for Earth to tell it to stop before driving off a cliff.
The Solution: tpt-t-space-rover uses onboard predictive autonomy. It generates a local Digital Elevation Model (DEM) from stereo cameras at 10Hz. A custom, SIMD-accelerated path planner evaluates thousands of potential trajectories in <50 milliseconds, selecting the safest path that adheres to tilt and traction limits, entirely without ground intervention.
4.5. Graceful Degradation & Safe Mode
When anomalies occur, the system must protect the asset above all else.
The Solution: tpt-t-space-thermal and tpt-t-space-power continuously monitor health. If a critical threshold is crossed (e.g., battery temperature < -20°C), the system instantly triggers Safe Mode: non-essential payloads are powered down, the spacecraft slews to a sun-pointing attitude for power/heat, and a low-rate beacon is transmitted via DTN. This state transition is a single, atomic, zero-allocation operation.
5. The "Space Operations" Feature Matrix (v1)
5.1. Planetary Rovers
Autonomous Traverse: Point-to-point navigation with real-time slip detection and hazard avoidance.
Science Sequencing: Execution of complex, multi-sol instrument deployment sequences (e.g., drill, sieve, spectrometer analysis) with automatic rollback on failure.
Wheel Health Monitoring: Tracks motor current and visual wheel wear to detect impending failures (e.g., Curiosity wheel damage).
5.2. Satellite Constellations & ADCS
Precision Pointing: Sub-arcsecond attitude control for Earth observation or deep-space telescopes.
Formation Flying: Multiple satellites maintaining precise relative orbits for interferometry or synthetic aperture radar (SAR), using inter-satellite links.
Momentum Management: Automated reaction wheel desaturation (momentum dumping) using magnetorquers or thrusters.
5.3. Orbital Rendezvous & Docking
Relative Navigation: Fuses LiDAR, visual markers, and GPS (if in LEO) for cm-level relative state estimation.
Autonomous Docking: Model-predictive control for final approach, managing plume impingement and collision avoidance.
Robotic Manipulation: 7-DOF space arm control with singularity avoidance and payload mass estimation.
5.4. Deep Space & Survival
Cruise Phase Management: Ultra-low-power "hibernation" modes with periodic wake-ups for trajectory correction maneuvers (TCMs).
Radiation Storm Response: Automatically powers down sensitive electronics and reorients the spacecraft to use its fuel tank or structure as a radiation shield during solar particle events.
6. The Complete "Mars Sample Collection" Data Flow
Here is the lifecycle of an autonomous rover operation during a communications blackout, demonstrating the zero-allocation, fault-tolerant flow:
The Command: Earth uplinks a "Proceed to Waypoint Alpha and collect sample" bundle via tpt-t-space-dtn. The rover acknowledges custody transfer and stores the command in NVRAM.
The Blackout: Mars rotates, blocking the line-of-sight to the orbiter. The rover is now entirely on its own for the next 4 hours.
Autonomous Traverse: tpt-t-space-rover begins moving. tpt-t-space-predictive processes stereo camera data, generating a local DEM. It detects a 25-degree slope ahead (exceeding the 20-degree safety limit).
Replanning: The path planner instantly recalculates a 15-meter detour around the hazard. The entire replan takes 40 milliseconds. No ground input is required.
The Anomaly: A high-energy cosmic ray strikes the navigation CPU, flipping a bit in a temporary variable (SEU).
Rad-Hard Recovery: tpt-t-space-radiation's TMR voter detects a mismatch between the three redundant calculation cores. It discards the corrupted result, uses the majority vote, and flags the affected core for a hardware watchdog reset. The rover's path is unaffected.
Sample Collection: The rover reaches Waypoint Alpha. It executes the pre-loaded science sequence: deploy arm, press drill, extract core, seal tube, and stow in the sample carousel. Each step is verified by torque and position sensors.
Safe Mode Trigger: A dust storm darkens the sky. tpt-t-space-power detects solar array output dropping below the survival threshold. It instantly triggers Safe Mode: the science payload is powered down, and the rover halts all movement to conserve battery.
Reconnection: The storm clears, and the orbiter passes overhead. tpt-t-space-dtn automatically resumes, transmitting the complete, hash-verified telemetry log and a "Safe Mode" alert to Earth, awaiting new commands.

8. Developer Experience & Simulation
Testing space software on Earth requires mimicking conditions that are fundamentally impossible to perfectly replicate (microgravity, vacuum, radiation). tpt-teleop-space relies on rigorous, physics-accurate simulation.
tpt-t-space-sim: A headless simulator that models:
6DOF orbital mechanics (J2 perturbations, atmospheric drag, third-body gravity)
Spacecraft mass properties and reaction wheel/CMG dynamics
Sensor noise models (star tracker blinding, gyro bias drift, IMU noise)
Radiation environment (injecting random bit flips into memory to test TMR/scrubbing)
DTN network blackouts and delay profiles (e.g., Mars-Earth light time)
Visualizer: A lightweight egui (MIT) binary that renders:
3D orbital trajectories and ground tracks
Spacecraft attitude (quaternion visualization) and sun-vector alignment
Rover terrain maps and planned vs. actual paths
Power/thermal budgets over time
The simulator runs at variable speeds, allowing developers to test multi-year cruise phases or complex orbital rendezvous maneuvers in minutes of wall-clock time.

A Mars rover is exploring a crater. The operator is on Earth, 12 light-minutes away.

Domain-Specific Adaptation:

Bandwidth Optimization: The adapter compresses images and telemetry to minimize bandwidth usage over the deep-space link.
